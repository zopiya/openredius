# Post-MVP 运行模型与产品演进

## 目标

在 M0–M7 已完成的单实例准入控制台基础上，定义下一阶段的产品优先级、职责边界和可执行
SOP，使团队能安全地把系统投入日常运营，而不是只拥有一套可部署的功能集合。

## 范围

- 建立产品能力分层与明确的实施顺序。
- 定义业务职责与现有 RBAC 的映射，以及后续权限模型的演进边界。
- 定义策略变更、NAS 生命周期、告警事件、恢复演练和审计的 SOP。
- 将已预留但未实现的能力标明为候选项，不承诺实现日期。

## 非范围

- 不修改 API、数据库、前端或部署实现。
- 不选定新的第三方供应商、协议库或商业产品。
- 不改变 M0–M7 已接受 ADR 的技术决定。

## 验收标准

- 评审者能据文档判断每项候选能力的价值、前置条件、优先级和完成信号。
- 每一项高风险日常操作均有责任人、审批要求、执行步骤和证据留存要求。
- 文档索引与路线图能定位这份后续规划。
